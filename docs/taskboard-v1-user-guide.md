# Codex Taskboard V1 使用说明

## 你每天只需要做什么

Snow 日常只负责四件事：

1. 新建任务并说明目标；
2. 必要时补充评论或附件；
3. 调整优先级或截止日期；
4. 验收结果并点击完成。

正常流程不需要 Snow 手工维护“待认领、处理中、遇到阻碍、等你确认”的状态。

## 首次配置

自动认领按项目启用。每个需要自动执行的项目只配置一次：

1. 左上角切换到具体项目；
2. 打开右上角“自动化”；
3. 开启“自动认领开关”，选择模型和推理强度；
4. 回到全局视图日常使用。

全局视图会统一调度所有已开启自动认领的项目。V1 的调度器运行在已打开的 Taskboard 页面中，因此需要保持 Codex 和 Taskboard 页面打开。

## 新建任务

日常可以直接停留在“全局”：

1. 点击右上角加号或状态栏加号；
2. 写清任务标题、目标、完成标准和必要材料；
3. 系统先推荐所属项目；推荐正确就直接保存，错误时只改项目下拉框；
4. 有明确项目的任务进入“待认领”；无法可靠判断项目的任务保存到“待立项”，不会空转。

新任务不需要先建立或关联会话。自动认领时会创建唯一主执行会话，并命名为 `Taskboard · 任务标题`。

## 自动流转

| 看板状态 | 含义 | Snow 的动作 |
| --- | --- | --- |
| 待立项 | 项目或执行信息不足 | 补全后选择项目并改为待认领 |
| 待认领 | 已进入自动调度队列 | 等待即可 |
| 处理中 | Agent 正在主执行会话推进 | 通常无需操作 |
| 遇到阻碍 | 缺材料、权限或业务决定 | 直接在卡片补评论或附件 |
| 等你确认 | Agent 已提交本轮结果 | 通过就点完成；不通过就在卡片或会话提出修改 |
| 完成 | Snow 已确认可用 | 无需操作 |

任务被认领、提交结果、收到返工意见时，状态会自动变化。会话暂时空闲不会被误判为完成。

## 评论、附件和原会话

- 在任务卡片里评论或补附件，会自动唤醒同一个主执行会话。
- 在主执行会话里提出修改，Taskboard 检测到会话重新运行后会把“等你确认”改回“处理中”。
- 阻碍任务收到卡片新材料后，Agent 先判断材料是否真的解决问题；解决后才回到“处理中”，否则继续停在“遇到阻碍”并说明还缺什么。
- 刷新、定时检查和追加意见都不应产生第二个主执行会话。

## 全局面板怎么看

- “处理中”：当前正在推进的任务；卡片显示目标、当前阶段、最近完成、下一步和最后活动时间。
- “遇到阻碍”：当前需要 Snow 补材料、权限或决定的任务。
- “等你确认”：Agent 已交付、等待 Snow 验收的任务。
- “待认领”：已准备好但尚未获得执行资源的队列。

调度顺序依次为：今天到期或逾期、截止日期更近、优先级更高、创建更早。全局最多并行三个任务；相同代码工作目录不会并行改动。

## 历史会话怎么处理

V1 不要求整理全部历史会话。只把仍在推进、确实需要纳入管理的工作建立成任务；已经结束或短期不会继续的历史会话可以归档。

V1 的完整自动流程主要面向 Taskboard 新建并自动认领的任务。旧任务若只是手工绑定了任意历史会话，系统会保留关联，但不会强行接管或创建第二个会话。

## 首轮验收建议

不用再造 Finance 测试任务。下一项真实工作到来时，直接从全局创建一张低风险任务卡，观察：

1. 项目是否推荐正确；
2. 是否只创建一个易读名称的主执行会话；
3. 是否自动进入处理中；
4. 提交结果后是否进入等你确认；
5. 提出一次小修改后是否复用原会话并自动回到处理中。

已有阻碍任务下次需要补材料时，可顺便验证“只在卡片补附件，原会话自动恢复”的路径。
